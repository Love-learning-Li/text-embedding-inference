> **项目背景**：将 `text-embedding-inference` 框架从 GPU/HPU 平台迁移到华为昇腾 NPU（`torch_npu`），使 Qwen3 模型能够在 NPU 上正确运行并输出文本 Embedding。本报告逐文件对比原始代码与修改后代码，详细分析每一处修改的目的、原因与思路。

## 1. `flash_qwen3.py` — 模型主体文件

### 修改概览

这是改动最大的文件，核心目标是：
- 引入 NPU 专用算子（`torch_npu`）
- 将 Tensor 布局从 BNSD（标准 4D batch 格式）迁移至 **TND（Token-Number-Dimension，即变长序列压缩格式）**
- 支持单文件和分片模型两种权重加载方式
- 增加完善的调试日志基础设施（已在正式运行时关闭）
- 修复 `FlashQwen3.embed` 中的 pooling 调用与 Tensor 重组逻辑

---

**位置**：文件头部，第 2 行、第 17-18 行

**原始代码**：
```python

```

**修改后代码**：

```python
import json
from loguru import logger

```

**修改目的**：引入 NPU 算子库与日志基础设施。

**修改原因**：
- `torch_npu` 是华为昇腾 NPU 的 PyTorch 扩展，提供 `npu_rms_norm`、`npu_rotary_mul`、`npu_fusion_attention` 等专用高性能算子。
- `loguru` 用于结构化日志输出，便于调试过程中追踪 Tensor shape 和算子调用路径。
- `datetime` 用于调试日志中打印时间戳（后已注释）。

**修改思路**：NPU 适配的第一步，所有 NPU 专用算子都通过 `torch_npu` 命名空间访问。

### 修改点 2：新增日志基础设施

**位置**：第 22-67 行

**原始代码**：无任何日志相关代码。

**修改后代码**：
```python
_LOGGED_ONCE_KEYS = set()
SHAPE_LOG_LEVEL = "warning"
_NPU_ROTARY_TND_AVAILABLE = False
DEBUG_LOGGING_ENABLED = False

def log_once(level, key, message): ...
def log_shape_once(key, message): ...
def log_tensor_stats(name, tensor, module_name): ...
def log_separator(title, module_name): ...
```

**修改目的**：在调试期间追踪每个 Tensor 的 shape、dtype、均值/方差等统计信息，同时避免重复打印相同的警告日志。

**修改原因**：NPU 适配过程中，Tensor layout 问题（如 BNSD vs TND、cos/sin shape 不匹配）是最常见的错误来源。需要精确的 shape 日志来定位问题，但又不能在每个 forward 调用时都输出，否则性能开销巨大。

**修改思路**：
- `log_once`：用 key-set 去重，同类警告只打印一次，避免日志洪泛。
- `DEBUG_LOGGING_ENABLED = False`：生产环境关闭，调试时开启，zero-cost 设计。
- `log_tensor_stats` 内部代码全注释掉：函数体保留但内容注释，方便日后重新开启而不改接口。

### 修改点 3：`load_weight` 函数 — 支持单文件模型

**位置**：第 70-83 行

**原始代码**：
```python
def load_weight(model_path, weight_map, name, dtype, device):
    target_file = weight_map[name]  # 直接用 weight_map 字典索引
    with safe_open(f"{model_path}/{target_file}", framework="pt") as f:
        return f.get_tensor(name).to(dtype).to(device)
```

**修改后代码**：
```python
def load_weight(model_path, weight_map, name, dtype, device):
    if weight_map is None:
        # 单文件模型
        with safe_open(f"{model_path}/model.safetensors", framework="pt") as f:
            return f.get_tensor(name).to(dtype).to(device)
    else:
        # 分片模型
        target_file = weight_map[name]
```

**修改目的**：让代码同时支持单文件（`model.safetensors`）和分片模型（带 `index.json` 的多文件）。

**修改原因**：原始代码假设模型一定是分片格式（需要 `weight_map_json["weight_map"]` 字典），但实验环境中使用的小型 Qwen3 模型是单文件格式，导致 `KeyError`。

**修改思路**：将 `weight_map` 约定为 `None`（单文件）或字典（分片），在函数内部做分支处理，对上层调用者透明。

### 修改点 4：新增 NPU 旋转位置编码（RoPE）实现

**位置**：第 85-218 行（全新内容，替换原来的简单 `apply_rotary_pos_emb`）

**原始代码**：
```python
def apply_rotary_pos_emb(q, k, cos, sin, unsqueeze_dim=1):
    cos = cos.unsqueeze(unsqueeze_dim)
    sin = sin.unsqueeze(unsqueeze_dim)
    q_embed = (q * cos) + (rotate_half(q) * sin)
    k_embed = (k * cos) + (rotate_half(k) * sin)
    return q_embed, k_embed
```

**修改后代码**（精简展示核心结构）：
```python
_NPU_ROTARY_TND_AVAILABLE = False
NPU_ROTARY_USE_NATIVE_MATMUL = False

def apply_rotary_pos_emb(q, k, cos, sin, unsqueeze_dim=1):
    # 入口，统一路由到 npu_rotary 实现
    return _apply_rotary_pos_emb_npu_rotary(q, k, cos, sin, unsqueeze_dim)

def _apply_rotary_pos_emb_native(q, k, cos, sin, unsqueeze_dim=1):
    # 原生矩阵乘法实现，TND 格式最优路径
    ...

def _apply_rotary_pos_emb_npu_rotary(q, k, cos, sin, unsqueeze_dim=1):
    # 尝试调用 torch_npu.npu_rotary_mul，失败则回退 native
    if not _NPU_ROTARY_TND_AVAILABLE:
        return _apply_rotary_pos_emb_native(...)
    try:
        q_embed = torch_npu.npu_rotary_mul(q, cos_npu, sin_npu)
        ...
    except RuntimeError:
        _NPU_ROTARY_TND_AVAILABLE = False
        return _apply_rotary_pos_emb_native(...)
```

**修改目的**：
1. 适配 TND（Token-Number-Dimension）格式的 3D Tensor，原始实现假设 4D BNSD 格式，会导致 `unsqueeze` 维度错误。
2. 尝试利用 NPU 专用算子 `npu_rotary_mul` 提升性能，同时保留原生回退路径保证正确性。

**修改原因**：
- TND 格式中 q/k shape 为 `[T, N, D]`（T = 所有序列总 token 数，N = 头数，D = 头维度），而原始 `unsqueeze(dim=1)` 是为 `[B, S, N, D]` 这种 4D 格式设计的，维度对不上会导致广播错误或静默的计算错误。
- `npu_rotary_mul` 是华为 NPU 的融合算子，可将旋转编码计算融合到一个算子中，理论上比两次矩阵乘法更快，但要求特定的输入 layout，需要严格校验。

**修改思路**：
- 用 `_NPU_ROTARY_TND_AVAILABLE` 全局标志控制是否启用 NPU 算子，若 `RuntimeError`（算子版本不支持等）则自动降级。
- `_apply_rotary_pos_emb_native` 中增加多种 cos/sin shape 的归一化逻辑（`_normalize_coeff_for_tnd_native`），兼容 `[T,D]`、`[1,T,D]`、`[T,1,D]` 等多种输入形态，避免上游输出格式变化导致 RoPE 失效。
- 当前 `_NPU_ROTARY_TND_AVAILABLE = False`，即默认走 native 路径，`npu_rotary_mul` 路径作为预留优化。

### 修改点 5：`Qwen3RMSNorm.forward` — 使用 NPU 融合算子

**位置**：第 263-281 行

**原始代码**：
```python

    input_dtype = hidden_states.dtype
    hidden_states = hidden_states.to(torch.float32)
    variance = hidden_states.pow(2).mean(-1, keepdim=True)
    hidden_states = hidden_states * torch.rsqrt(variance + self.variance_epsilon)
```

**修改后代码**：

```python
    # 原始的 float32 手动实现已注释掉
```

### 修改点 7：`Qwen3Attention.forward` — TND 格式校验与 GQA 支持

**位置**：第 345-403 行

**原始代码**（关键差异部分）：
```python
def forward(self, hidden_states, position_embeddings, cu_seqlens, max_s, attn_mask=None):
    input_shape = hidden_states.shape[:-1]
    hidden_shape = (*input_shape, -1, self.head_dim)  # 动态推断头数

    q = self.q_norm.forward(F.linear(hidden_states, self.q_proj_weight).view(hidden_shape))
    k = self.k_norm.forward(F.linear(hidden_states, self.k_proj_weight).view(hidden_shape))
    v = F.linear(hidden_states, self.v_proj_weight).view(hidden_shape)
    cos, sin = position_embeddings
    q, k = apply_rotary_pos_emb(q, k, cos, sin, unsqueeze_dim=2)  # unsqueeze_dim=2
    attn_output = torch.empty_like(q)
    attention(q, k, v, attn_output, cu_seqlens, ...)  # 无 num_heads
```

**修改后代码**（关键差异部分）：
```python
def forward(self, hidden_states, position_embeddings, cu_seqlens, max_s, attn_mask=None):
    if hidden_states.dim() != 2:  # 新增：TND 格式强制校验
        raise ValueError(...)

    input_shape = hidden_states.shape[:-1]
    q_proj_out = F.linear(hidden_states, self.q_proj_weight)
    q = self.q_norm.forward(
        q_proj_out.view(*input_shape, self.num_heads, self.head_dim)  # 明确指定 num_heads
    )
    k_proj_out = F.linear(hidden_states, self.k_proj_weight)
    k = self.k_norm.forward(
        k_proj_out.view(*input_shape, self.num_key_value_heads, self.head_dim)  # 明确 GQA 头数
    )
    v = F.linear(hidden_states, self.v_proj_weight).view(
        *input_shape, self.num_key_value_heads, self.head_dim
    )
    q, k = apply_rotary_pos_emb(q, k, cos, sin, unsqueeze_dim=1)  # unsqueeze_dim=1

    if self.num_key_value_groups > 1:  # 新增：GQA 头扩展
        k = k.repeat_interleave(self.num_key_value_groups, dim=1)
        v = v.repeat_interleave(self.num_key_value_groups, dim=1)

    attention(q, k, v, self.num_heads, attn_output, cu_seqlens, ...)  # 新增 num_heads 参数
```

**修改目的**：
1. 解决 GQA（Grouped Query Attention）中 k/v 头数少于 q 头数的情况。
2. 修正 TND 格式下 `unsqueeze_dim` 的正确值。
3. 传递 `num_heads` 给 `attention` 函数（NPU 算子需要）。

**修改原因**：
- Qwen3 使用 GQA，`num_key_value_heads`（如 8）< `num_attention_heads`（如 32），原始 `hidden_shape = (*input_shape, -1, self.head_dim)` 会让 q/k/v 都用 32 个头，加载 k_proj 权重时 shape 不匹配。
- TND 格式中 Tensor 是 `[T, N, D]`，N 维在 dim=1，所以 `unsqueeze_dim=1`；而原始 BNSD 格式是 `[B, S, N, D]`，N 在 dim=2，所以原始用 `unsqueeze_dim=2`。
- `npu_fusion_attention` 需要显式传入 `head_num`，不能通过 Tensor shape 自动推断。

**修改思路**：
- `repeat_interleave` 是标准的 GQA 兼容做法，将 k/v 从 `num_key_value_heads` 扩展到 `num_heads`，与 q 对齐后再做注意力计算。
- 在 `forward` 入口增加 `dim() != 2` 的断言，让错误在 Attention 层就暴露，而不是在 NPU 算子里以不明错误失败。

### 修改点 8：`Qwen3MLP.forward` — 展开中间变量

**位置**：第 439-445 行

**原始代码**：
```python
def forward(self, hidden_state):
    gated_hidden_states = F.linear(hidden_state, self.gate_proj_weight)
    uped_hidden_states = F.linear(hidden_state, self.up_proj_weight)
    return F.linear(
        self.act_fn(gated_hidden_states) * uped_hidden_states,
        self.down_proj_weight,
    )
```

**修改后代码**：
```python
def forward(self, hidden_state):
    gated_hidden_states = F.linear(hidden_state, self.gate_proj_weight)
    uped_hidden_states = F.linear(hidden_state, self.up_proj_weight)
    activated = self.act_fn(gated_hidden_states)     # 新增中间变量
    multiplied = activated * uped_hidden_states       # 新增中间变量
    output = F.linear(multiplied, self.down_proj_weight)  # 新增中间变量
    return output
```

**修改目的**：将计算步骤拆开，便于调试时在每个中间步骤插入 `log_tensor_stats`。

**修改原因**：MLP 的激活值异常（如 NaN、Inf）是训练/推理中常见问题，展开中间变量后可以精确定位是 gate、up、还是 down 投影出现了问题。

**修改思路**：此修改不影响计算结果，是纯粹的调试友好性改进。在确认正确性后可选择合并回单行写法。

### 修改点 10：`Qwen3RotaryEmbedding.forward` — 修复 1D position_ids 处理 & device_type 修正

**位置**：第 515-549 行

**原始代码**：

**修改后代码**：

```python
    if position_ids.dim() == 1:         # 新增：处理 1D TND 格式的 position_ids
        position_ids = position_ids.unsqueeze(0)  # [T] -> [1, T]
```

```python
def embed(self, batch):
    if isinstance(batch, FlashBatch):
        cu_seqlens = batch.cu_seqlens
        input_ids = batch.input_ids
        position_ids = batch.position_ids

        # TND 格式安全检查：强制展平为 1D

            last_indices = (cu_seqlens[1:] - 1).to(...)
            embedding = hidden_states.index_select(0, last_indices)
            return [Embedding(values=...) for i in range(len(batch))]

        # 通用路径：将 TND 格式重组为 [B, S, H] 后走 pooling
        batch_hidden_states = torch.zeros((batch.size, batch.max_s, self.hidden_size), ...)
        pooling_attention_mask = torch.zeros((batch.size, batch.max_s), dtype=torch.long, ...)
        offset = 0
        for i, seq_len in enumerate(seq_lens):
            batch_hidden_states[i, :seq_len, :] = hidden_states[offset:offset + seq_len, :]
            pooling_attention_mask[i, :seq_len] = 1
            offset += seq_len

        output = BaseModelOutputWithPast(last_hidden_state=batch_hidden_states)
    else:
        raise TypeError("[FlashQwen3.embed] FlashBatch(TND) is required on NPU, ...")

    embedding = self.pooling.forward(output, pooling_attention_mask)
    ...
```

**修改目的**：
1. 彻底适配 TND 格式——模型输出是 `[T, H]`（所有序列拼接），而非 `[B, S, H]`（padding 批次）。
2. 修复 pooling 调用时传入错误的 `attention_mask`（`FlashBatch` 没有 `attention_mask` 字段）。
3. 为 `last` pooling 增加高效快速路径，避免不必要的 Tensor 重组开销。
4. 删除 `PaddedBatch` 分支（NPU 不支持，明确 raise TypeError）。

**修改原因**：
- 原始代码 `embedding = self.pooling.forward(output, batch.attention_mask)` 会在 `FlashBatch` 分支抛出 `AttributeError`，因为 `FlashBatch` 没有 `attention_mask` 字段。
- TND 格式下模型输出 `last_hidden_state` 是 `[T, H]` 而非 `[B, S, H]`，直接送给 pooling（期望 3D 输入）会维度不匹配。
- `last` pooling 只需要每个序列最后一个 token，利用 `cu_seqlens` 直接计算索引比重组整个 `batch_hidden_states` 要高效得多。

**修改思路**：
- 先判断是否可以走快速路径（`last` pooling），可以则直接返回，避免 O(B×S×H) 的零填充分配。
- 不能走快速路径时，将 TND 格式手动重组为 `[B, S, H]` 并构造对应的 `attention_mask`，再交给 pooling 层处理，保持 pooling 层接口不变。

**原始代码**：`DefaultPooling` 直接委托给 `sentence_transformers.Pooling`。

**修改后代码**：新增四个独立 Pooling 类：

```python
class MeanPooling(_Pooling):
    # 对有效 token 取加权平均
    def forward(self, model_output, attention_mask) -> Tensor:
        token_embeddings = model_output[0]
        attention_mask_expanded = attention_mask.unsqueeze(-1).expand(...).float()
        sum_embeddings = torch.sum(token_embeddings * attention_mask_expanded, dim=1)
        sum_mask = torch.clamp(attention_mask_expanded.sum(dim=1), min=1e-9)
        return sum_embeddings / sum_mask

class MaxPooling(_Pooling):
    # 取各维度最大值（忽略 pad token）
    ...

class CLSPooling(_Pooling):
    # 取第一个 token（[CLS]）
    def forward(self, model_output, attention_mask) -> Tensor:
        return model_output[0][:, 0, :]

class LastTokenPooling(_Pooling):
    # 取最后一个真实 token（适合 decoder-only 模型）
    def forward(self, model_output, attention_mask) -> Tensor:
        token_embeddings = model_output[0]
        attention_mask = attention_mask.to(dtype=torch.bool)
        last_indices = attention_mask.sum(dim=1, keepdim=True) - 1
        last_indices = last_indices.clamp(min=0)
        last_indices_expanded = last_indices.unsqueeze(-1).expand(-1, -1, token_embeddings.shape[-1])
        return token_embeddings.gather(1, last_indices_expanded).squeeze(1)
```

**修改目的**：为各种 pooling 策略提供独立、可测试的原生实现。

**修改原因**：
- `MeanPooling`/`MaxPooling`/`CLSPooling`：直接 PyTorch 实现，去掉 `sentence_transformers` 中间层。
- `LastTokenPooling`：这是新增的最关键类，专为 decoder-only 模型（Qwen3）设计。`sentence_transformers.Pooling` 不原生支持 `last` 模式（或实现有差异），需要自行实现。实现原理：通过 `attention_mask.sum(dim=1)` 计算每个序列的实际长度，减 1 得到最后 token 的索引，再用 `gather` 提取。

## 5. 跨文件修改总结

### 核心主线：TND 格式适配

整个调试过程的最核心改动是将数据格式从 **BNSD**（Batch × Sequence_len × NumHeads × HeadDim，padding 格式）迁移到 **TND**（Total_tokens × NumHeads × HeadDim，变长序列压缩格式）。这是一个贯穿所有文件的系统性改动：

| 文件 | TND 适配内容 |
|------|------------|
| `types.py` | `cu_seqlens` 放 CPU，便于 TND 格式的序列长度控制 |
| `flash_qwen3.py` | `embed` 中处理 1D `input_ids`/`position_ids`；`RotaryEmbedding` 处理 1D `position_ids`；`Attention` 中 `unsqueeze_dim=1`（TND 的 N 维在 dim=1）|
| `flash_attn.py` | `npu_fusion_attention` 使用 `input_layout="TND"`；`cu_seqlens` → `actual_seq_qlen` 的转换逻辑 |
| `pooling.py` | 新增 `LastTokenPooling`，处理从 TND 重组后的 `[B, S, H]` 张量 |

### 核心主线：NPU 算子替换

| 原始实现 | NPU 替换实现 | 所在文件 |
|---------|------------|--------|
| 手动 RMS Norm（float32 cast）| `torch_npu.npu_rms_norm` | `flash_qwen3.py` |
| 标准矩阵乘法 RoPE | `torch_npu.npu_rotary_mul`（保留 native 回退）| `flash_qwen3.py` |
| `flash_attn_cuda.fwd` / `flash_attn_2_cuda.varlen_fwd` | `torch_npu.npu_fusion_attention` | `flash_attn.py` |
| `sentence_transformers.Pooling` | 原生 PyTorch 实现 | `pooling.py` |

### 接口链路变化

原始调用链：
```
FlashQwen3.embed(FlashBatch)
  → model.forward(batch.input_ids [2D?], batch.position_ids [2D?])
  → attention(q, k, v, out, cu_seqlens, ...)   # 无 num_heads
  → pooling.forward(output, batch.attention_mask)  # FlashBatch 无此字段！
```

修改后调用链：
```
FlashQwen3.embed(FlashBatch)
  → [flatten input_ids/position_ids to 1D]
  → model.forward(input_ids [1D], position_ids [1D])
  → attention(q, k, v, num_heads, out, cu_seqlens, ...)  # 新增 num_heads
  → [快速路径] hidden_states.index_select(0, last_indices) → return
  → [通用路径] 重组 [B,S,H] + 构造 pooling_attention_mask
  → pooling.forward(output, pooling_attention_mask)  # 新构造的 mask
```

### 设计原则总结

1. **稳健性优先**：所有 NPU 算子调用都有 try/except + fallback，保证在算子不可用时仍能正常运行（性能降低但不崩溃）。
2. **向后兼容**：原始的手动实现（如 RMS Norm、RoPE）保留为注释状态，便于回退和对照。
3. **单一职责**：`types.py` 只管 Batch 格式，`pooling.py` 只管 Pooling 策略，`flash_attn.py` 只管 Attention 算子，`flash_qwen3.py` 是顶层编排——职责清晰，改动影响面可控。
4. **调试基础设施**：`log_once`、`log_shape_once`、`_npu_warn_once` 等工具虽然在生产环境关闭，但在调试阶段提供了宝贵的可观测性，是快速定位 shape 错误的关键。

**上一版本代码（关键行）**：

**最新版本代码**：
```python
q = self.q_norm.forward(
    torch_npu.npu_linear(hidden_states, self.q_proj_weight, bias=None).view(*input_shape, self.num_heads, self.head_dim)
)
k = self.k_norm.forward(
    torch_npu.npu_linear(hidden_states, self.k_proj_weight, bias=None).view(*input_shape, self.num_key_value_heads, self.head_dim)

# ...

attn_output = torch_npu.npu_linear(attn_output, self.o_proj_weight, bias=None)
```

**修改目的**：将所有矩阵乘法（投影层）替换为 NPU 融合算子 `torch_npu.npu_linear`，提升计算效率。

**修改原因**：
- `torch.nn.functional.linear` 在 NPU 上会被路由到通用矩阵乘法（GEMM）算子，经过 PyTorch dispatch 体系，存在额外的调度开销。
- `torch_npu.npu_linear` 是华为昇腾 NPU 的原生 linear 算子，可以更好地利用 NPU 的矩阵计算单元（Cube Unit），减少算子调度延迟。
- 显式传 `bias=None` 比省略 bias 参数更清晰，同时告知 NPU 算子无需分配 bias 加法操作，节省一次算子调度。

**修改思路**：这是性能优化（`a82da4c` 提交"经过一轮性能优化"）和代码精简的核心改动之一。替换是逐一进行的——q/k/v 投影和 o 投影都改为 `npu_linear`，保持代码结构不变，只替换底层算子。

**上一版本 `Qwen3MLP.forward`**（展开中间变量的调试版本）：

```python
    uped_hidden_states = F.linear(hidden_state, self.up_proj_weight, bias=None)
```

**最新版本 `Qwen3MLP.forward`**：
```python
def forward(self, hidden_state):
    # [注释掉的旧版逐步实现]
    # gated_hidden_states = torch_npu.npu_linear(...)
    # uped_hidden_states = torch_npu.npu_linear(...)
    # return torch_npu.npu_linear(self.act_fn(...) * ..., ...)

    gate_up_states = torch_npu.npu_linear(hidden_state, self.gate_up_proj_weight, bias=None)
    hidden_states = torch_npu.npu_swiglu(gate_up_states, dim=-1)
    return torch_npu.npu_linear(hidden_states, self.down_proj_weight, bias=None)
```

**修改目的**：
1. 将 gate 和 up 投影从两次 linear 合并为一次 linear（`gate_up_proj_weight`），减少一半的矩阵乘法算子调度开销。
2. 用 `torch_npu.npu_swiglu` 替代 `SiLU激活 + 元素乘` 两步操作，利用 NPU 融合算子一步完成 SwiGLU 计算。

**修改原因**：
- **权重合并（dim=0 拼接）**：`gate_up_proj_weight` 将 `[intermediate_size, hidden_size]` 的 gate 权重和同形状的 up 权重沿 dim=0 拼接为 `[2 * intermediate_size, hidden_size]`，一次 `npu_linear` 得到 `[T, 2 * intermediate_size]` 的输出，再由 `npu_swiglu` 从 dim=-1 切分并完成激活乘法。这是 LLM 推理中标准的 MLP 融合优化。
- **`npu_swiglu` 融合**：`npu_swiglu(x, dim=-1)` 等价于 `silu(x[..., :half]) * x[..., half:]`（SwiGLU），将激活（SiLU）和门控乘法两个操作融合为一个 NPU 算子，减少中间 Tensor 分配和两次算子调度。
- **`act_fn` 注释掉**：由于 `npu_swiglu` 内部已实现 SiLU 激活，不再需要外部的 `ACT2FN["silu"]`，因此注释掉，避免无效的函数对象持有。

**修改思路**：这是本次优化提交（`bcc1085`）中最重要的性能改动。MLP 在 Transformer 中占据约 2/3 的计算量，优化 MLP 的算子效率对整体推理速度影响最大。`gate_up_proj_weight` 合并策略与 `npu_swiglu` 的组合，是 Ascend NPU 上推荐的 Qwen/LLaMA 类模型 MLP 优化路径。

```python
def npu_attn(q, k, v, num_heads, out, attn_mask, seqlen_q, seqlen_k, ...):
    if is_causal:
        # 直接每次构造 [2048, 2048] causal mask，不再使用缓存函数

        )
        out_ = torch_npu.npu_fusion_attention(
            query=q, key=k, value=v,
            head_num=num_heads, input_layout="TND",
            scale=softmax_scale,
            actual_seq_qlen=seqlen_q.tolist(),   # 直接 .tolist()，不再处理首 0
            actual_seq_kvlen=seqlen_k.tolist(),
            sparse_mode=3,
            atten_mask=attn_mask_npu
        )[0]
    else:
        out_ = torch_npu.npu_fusion_attention(
            query=q, key=k, value=v,
            head_num=num_heads, input_layout="TND",
            scale=softmax_scale,
            actual_seq_qlen=seqlen_q.tolist(),
            actual_seq_kvlen=seqlen_k.tolist(),
        )[0]
    out.copy_(out_)
    return out
```

**删除的内容**：
- `_get_npu_compressed_causal_mask` 缓存函数（改为每次内联构造）
- `_npu_warn_once` 去重警告函数
- `_eager_varlen_tnd_attn` 手动 varlen attention 回退实现
- `NPU_COMPRESSED_MASK_SIZE`、`_NPU_COMPRESSED_MASK_CACHE`、`_NPU_WARN_ONCE_KEYS` 等全局变量
- `cu_seqlens` 首 0 剥离逻辑（`seqlen_q[1:] if ...` 的条件判断）
- try/except 容错包裹

**修改目的**：精简代码，去掉调试阶段保留的多余容错层。

**修改原因**：
- **删除首 0 剥离逻辑**：经过验证，`types.py` 中的 `cu_seqlens = torch.tensor(pb.cu_seq_lengths, dtype=torch.int32, device="cpu")` 构造的 tensor 格式稳定，`seqlen_q.tolist()` 得到的是 `[0, 5, 12, ...]` 格式（含首 0），而 `npu_fusion_attention` 实际接受这种格式（内部处理首 0）。因此不需要额外的格式转换。
- **删除 eager 回退**：`npu_fusion_attention` 在当前 CANN 版本下稳定运行，不再需要手动 softmax 的 fallback 实现。保留回退代码只会增加维护负担。
- **删除 mask 缓存**：`_get_npu_compressed_causal_mask` 的缓存是为了避免每次创建 `[2048, 2048]` bool tensor 的开销，但该 tensor 很小（256KB），在 NPU 上每次内联构造的开销可以忽略。缓存函数的存在反而增加了代码复杂度。

**修改思路**：这是从"防御性编程（调试模式）"向"精简确定性代码（生产模式）"的转变。调试阶段需要多层保护网，一旦每条路径都验证通过，就可以移除冗余层。

### 修改点 1：移除 `sentence_transformers` 依赖

**位置**：第 5 行（已删除）

**原始代码**：
```python

```

**修改后**：此行被完全删除。

**修改目的**：消除对 `sentence_transformers` 库的外部依赖。

**修改原因**：`sentence_transformers.models.Pooling` 的接口要求传入字典并返回字典，与项目直接张量操作的风格不符，且在 NPU 环境中引入额外的第三方依赖可能造成兼容性问题。

### 修改点 2：新增四个独立 Pooling 实现类

**位置**：第 16-68 行（全新内容）

**原始代码**：仅有 `DefaultPooling`（委托给 `sentence_transformers`）和 `SpladePooling`。

**修改后代码**：新增了四个完整实现：

```python
class MeanPooling(_Pooling):
    """对有效 token 取加权平均（除以有效 token 数量）"""
    def forward(self, model_output, attention_mask) -> Tensor:
        token_embeddings = model_output[0]
        attention_mask_expanded = attention_mask.unsqueeze(-1).expand(...).float()
        sum_embeddings = torch.sum(token_embeddings * attention_mask_expanded, dim=1)
        sum_mask = torch.clamp(attention_mask_expanded.sum(dim=1), min=1e-9)
        return sum_embeddings / sum_mask

class MaxPooling(_Pooling):
    """逐维度取最大值（padding 位置用 -1e9 填充屏蔽）"""
    def forward(self, model_output, attention_mask) -> Tensor:
        token_embeddings = model_output[0]
        attention_mask_expanded = attention_mask.unsqueeze(-1).expand(...).float()
        token_embeddings[attention_mask_expanded == 0] = -1e9
        return torch.max(token_embeddings, dim=1).values

class CLSPooling(_Pooling):
    """取第 0 个 token（[CLS] token，适合 BERT 类模型）"""
    def forward(self, model_output, attention_mask) -> Tensor:
        return model_output[0][:, 0, :]

class LastTokenPooling(_Pooling):
    """取每个序列最后一个真实 token（适合 decoder-only 模型）"""
    def forward(self, model_output, attention_mask) -> Tensor:
        token_embeddings = model_output[0]
        attention_mask = attention_mask.to(dtype=torch.bool)
        last_indices = attention_mask.sum(dim=1, keepdim=True) - 1
        last_indices = last_indices.clamp(min=0)
        last_indices_expanded = last_indices.unsqueeze(-1).expand(-1, -1, token_embeddings.shape[-1])
        return token_embeddings.gather(1, last_indices_expanded).squeeze(1)
```

**修改目的**：原生实现所有 pooling 策略，彻底去除第三方依赖，并新增 `LastTokenPooling`（Qwen3 这类 decoder-only 模型所需的 pooling 策略）。

**修改原因**：
- `MeanPooling`/`MaxPooling`/`CLSPooling`：这些是 `sentence_transformers.Pooling` 原本支持的策略，用纯 PyTorch 原生实现，逻辑直观、可调试。
- `LastTokenPooling`：这是最关键的新增类。`sentence_transformers.Pooling` 对 `last_token` 的支持历史上存在问题（不同版本行为不一致），而且其接口不直接支持 `cu_seqlens` 格式的变长序列。自行实现可以精确控制逻辑：通过 `attention_mask.sum(dim=1)` 计算真实序列长度，减 1 得到最后 token 索引，再用 `gather` 提取对应 embedding。

**修改后代码**：
```python
class DefaultPooling(_Pooling):
    def __init__(self, hidden_size, pooling_mode="last") -> None:  # 默认值改为 "last"
        assert pooling_mode != "splade", "..."
        if pooling_mode == "mean":
            self.pooling = MeanPooling(hidden_size, pooling_mode)
        elif pooling_mode == "max":
            self.pooling = MaxPooling(hidden_size, pooling_mode)
        elif pooling_mode == "cls":
            self.pooling = CLSPooling(hidden_size, pooling_mode)
        elif pooling_mode in ("last", "last_token"):
            self.pooling = LastTokenPooling(hidden_size, pooling_mode)
        else:
            self.pooling = LastTokenPooling(hidden_size, "last")  # 未知模式的安全 fallback
```

### 修改点 1：`FlashBatch.from_pb` — `cu_seqlens` 改为在 CPU 上构建

**位置**：第 116 行

**原始代码（`origin/origin_types.py`）**：
```python
cu_seqlens = torch.tensor(pb.cu_seq_lengths, dtype=torch.int32, device=device)
# device 是运行设备（NPU）
```

**修改后代码**：
```python
cu_seqlens = torch.tensor(pb.cu_seq_lengths, dtype=torch.int32, device="cpu")
# cu_seqlens = pb.cu_seq_lengths  # 注释掉的备选方案（直接用列表）
```

**修改目的**：强制将 `cu_seqlens` 张量保留在 CPU 内存中。

**修改原因**：
- `npu_fusion_attention` 的 `actual_seq_qlen`/`actual_seq_kvlen` 参数要求是 Python `list` 类型（见 `flash_attn.py` 中的 `seqlen_q.tolist()` 调用）。
- 如果 `cu_seqlens` 在 NPU 上，`.tolist()` 会触发 NPU→CPU 的数据同步（D2H 拷贝），这在每次 forward 调用时都会发生，增加额外延迟。
- 直接在 CPU 上保存 `cu_seqlens`，`.tolist()` 是纯 CPU 操作，零拷贝开销。
- `embed` 函数中用到的 `cu_seqlens[1:] - 1`（计算最后 token 索引）在 CPU tensor 上同样可以正确执行，且更方便后续 `embedding = hidden_states[last_token_indices]` 中的 CPU 索引操作（`hidden_states` 已 `.cpu()`）。

**修改思路**：`cu_seqlens` 是序列控制元数据，本质上是整数列表，放在 CPU 上访问最方便，且 NPU 算子也要求其最终以 Python list 形式传入。注释保留的 `# cu_seqlens = pb.cu_seq_lengths` 是最初考虑直接用 protobuf 列表（避免 tensor 构造开销）的备选方案，最终选择 tensor 是为了保留切片（`cu_seqlens[1:]`）等张量操作能力。

### 核心设计贯通：TND 格式与 NPU 算子生态

整个修改围绕一个核心设计决策展开：**使用 TND（Token × Num_heads × Dim）格式的变长序列**，而不是传统 padding 的 BNSD 格式。这一决策贯穿所有文件：

| 文件 | 角色 | TND 适配关键点 |
|------|------|--------------|
| `types.py` | 数据入口 | `cu_seqlens` 在 CPU；`FlashBatch` 不含 `attention_mask` |
| `flash_qwen3.py` | 模型主干 | `input_ids`/`position_ids` 均为 1D `[T]`；RoPE 对 1D position_ids 做 `unsqueeze(0)`；Attention 输出 reshape 为 `[T, H]` |
| `flash_attn.py` | 注意力算子 | `npu_fusion_attention(input_layout="TND")`；`actual_seq_qlen` 由 `cu_seqlens.tolist()` 提供 |
| `pooling.py` | 输出层 | 在 `embed` 中通过 `cu_seqlens` 索引直取，绕过需要 BNSD 格式的 pooling 类 |

### NPU 算子替换汇总

| 原实现 | NPU 替换算子 | 所在文件 | 优化效果 |
|-------|------------|---------|---------|
| 手动 RMS Norm（float32 升精） | `torch_npu.npu_rms_norm` | `flash_qwen3.py` | 融合算子，减少访存 |
| `F.linear`（4次，q/k/v/o 投影） | `torch_npu.npu_linear` | `flash_qwen3.py` | 减少 dispatch 开销 |
| 手动 RoPE（`rotate_half` + 矩阵乘） | `torch_npu.npu_rotary_mul` | `flash_qwen3.py` | 融合 RoPE，减少中间 tensor |
| 2次 `npu_linear` + `SiLU` + 元素乘 | `npu_linear`(合并权重) + `npu_swiglu` | `flash_qwen3.py` | 最大优化，MLP 从3步降至2步 |
| `flash_attn_cuda.fwd` | `torch_npu.npu_fusion_attention(TND)` | `flash_attn.py` | 原生 NPU 变长注意力 |
| `sentence_transformers.Pooling` | 原生 PyTorch 实现 | `pooling.py` | 去依赖，统一接口 |

### 调试方法论总结

1. **分层验证**：先保证输出格式（`4b6d154` - 跑通），再优化性能（`a82da4c`），再精简代码（`bcc1085`）。
2. **防御性开发后精简**：调试阶段保留多路 fallback（`_eager_varlen_tnd_attn`、`_NPU_ROTARY_TND_AVAILABLE`）和详细日志，验证稳定后逐步删除冗余代码。
3. **注释而非删除**：关键探索历史（多种 causal mask 方案、备用 RoPE 实现 `apply_rotary_pos_emb_npu1`）以注释形式保留，方便理解调试思路和快速回退。
4. **接口对齐先行**：`cu_seqlens` 格式（CPU + int32 + 含首0）、`attention` 函数签名（增加 `num_heads`）等接口问题在最早期就统一确定，避免后期大规模重构。
